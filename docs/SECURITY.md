# 安全与隐私模型

## 本地优先边界

- 设备发现、协议控制、密钥协商、文件拉取和解密均在本机 Rust 进程完成。
- 录音数据不会自动上传到安克、飞书或无界豆维护者控制的服务。
- AI 总结是显式操作：只有用户输入的转写文本会发送到用户配置的 API 地址。
- API Key 作为单次 Tauri 命令参数驻留内存，不写入 `.env`、浏览器存储或项目配置。

## 信任假设

1. 用户正在操作自己拥有或获授权管理的 D3200。
2. BLE 近距离链路和设备返回的 SoftAP 地址在本次会话中可信。
3. Windows 主机、WebView2、系统证书库和用户选择的 AI 服务没有被攻陷。

## 密码学材料生命周期

- P-256 私钥是每次连接临时生成的 `EphemeralSecret`。
- 32 字节会话密钥只保存在当前 `BleState` 内存中。
- 每个文件的 32 字节 AES 密钥仅在下载函数栈中使用。
- 源码、日志和错误信息不会输出 API Key、私钥、会话密钥或文件密钥。

## 自签名 WSS 的限制

D3200 本地 WSS 使用自签名证书，因此当前实现为本地设备连接放宽证书和主机名校验。为缩小风险：

- endpoint 的 host 必须与 BLE `1A/05` 返回的 host 完全一致；
- 放宽只发生在录音豆 WebSocket 客户端；AI HTTPS 请求仍使用标准信任链；
- 用户必须主动加入本次生成凭据的 SoftAP。

但这不等同于证书固定。具有本地网络或 BLE 控制能力的攻击者理论上可能冒充端点。未来若设备证书指纹可稳定获取，应实现证书指纹固定。

## 文件完整性防线

下载满足以下全部条件才会写入最终文件：

- 文件头 ID 等于用户选择的 ID；
- 文件头错误码为零；
- 解包材料以 `soundcored3200` 开头；
- 所有音频序号连续；
- 分片数与文件头传输长度一致；
- 收到明确的 `1A/0A` 完成帧。

当前协议没有提供端到端文件 MAC 或数字签名，因此这些检查主要防止错文件、截断、乱序和错误密钥，不能证明音频来源的密码学真实性。

## AI 端点校验

- 默认只接受 HTTPS。
- 仅 `localhost` 和 `127.0.0.1` 可使用 HTTP，便于连接本地模型。
- 非 2xx 响应只返回有限长度错误摘要，避免把无限响应展示到 UI。
- 用户应理解第三方 AI 提供商会接收到其主动提交的转写文本。

## 漏洞报告

公开仓库建立后，请通过 GitHub Security Advisory 私下报告能够泄露密钥、任意写文件、远程执行代码或绕过设备完整性检查的问题。不要在公开 Issue 中附带真实录音、设备序列号、API Key 或协议密钥。
